How we built it

The work followed a deliberate curation process — not a blind copy of all 76 pages:

  1. Reviewed all 76 cards in AwsKiro Docs/ and identified public-safe vs client-internal content
  2. Excluded client material — rollout plans (070–076), sync ops (061), working docs (067), live proofs with real ticket IDs (045, 046, 054), AWS access inventory (071)
  3. Condensed the best material into 8 purpose-built pages instead of publishing 76 overwhelming cards
  4. Sanitized all examples — real JIRA IDs (e.g. SASDPO-7809) replaced with generic ones (PROJ-1234); team and client names removed
  5. Rebranded from "AwsKiro" to Enhanced KIRO Framework for the consulting site audience
  6. Moved to a dedicated private repo FFJ-DocsPublic (removed from FFJ-CONSULTING-LLC)

What it takes to publish on the website

Publishing means making the docs reachable at a URL like https://ffjconsultingllc.com/docs/enhanced-kiro/. Here are the steps:

Step 1 — Copy docs to the deployable location

The live site serves static files from frontend/public/. Copy the entire folder:

cp -r /Users/fjabbari/REPO_CURSOR/FFJ-DocsPublic/ \
  /Users/fjabbari/REPO_CURSOR/FFJ-CONSULTING-LLC/frontend/public/docs/enhanced-kiro/

Step 2 — Add a card to the deployed docs portal

Add an "Enhanced KIRO" card to frontend/public/docs/index.html (and keep Docs/index.html in sync):

<div class="card enhanced-kiro-card">
    <div class="card-icon">⚡</div>
    <h2 class="card-title">Enhanced KIRO</h2>
    <p class="card-description">Enterprise AI development framework…</p>
    <a href="enhanced-kiro/index.html" class="card-link">View Documentation →</a>
</div>

Step 3 — Add website navigation (optional but recommended)

Update frontend/src/components/Navigation.jsx to add a link, for example:

<li><a href="/docs/enhanced-kiro/" target="_blank">Enhanced KIRO</a></li>

Optionally add an entry to frontend/src/data/tools.json for the Tools section on the home page.

Step 4 — Remove the draft banner

Before publishing, remove the yellow "Draft for review" banner from FFJ-DocsPublic/index.html (or its copy in frontend/public/docs/enhanced-kiro/index.html).

Step 5 — Build, commit, and deploy

cd /Users/fjabbari/REPO_CURSOR/FFJ-CONSULTING-LLC
git add frontend/public/docs/ frontend/src/
git commit -m "Publish Enhanced KIRO documentation to website"
./deploy-with-new-domain.sh

This builds the React frontend, syncs to S3 bucket ffj-consulting-website, and invalidates CloudFront distribution E3545N3N8YO2FZ.

Step 6 — Verify after deploy

  1. Open https://ffjconsultingllc.com/docs/enhanced-kiro/
  2. Hard refresh (Cmd+Shift+R) or use incognito if cached
  3. Check all 8 pages and Mermaid diagrams render correctly

Before you publish — review checklist

  • Read all 8 pages — tone, accuracy, numbers you're comfortable sharing publicly
  • Confirm no client names, ticket IDs, or internal URLs slipped through
  • Decide on final branding ("Enhanced KIRO" vs "FFJ Enhanced KIRO Framework")
  • Remove the draft review banner from the portal page
  • Sync Docs/ and frontend/public/docs/ (this unpublished-work card included)

Keeping docs in sync over time

When AwsKiro internal docs are updated, the workflow is:

  1. Update source material in ~/REPO_AI/AwsKiro/Docs/
  2. Re-curate and update pages in FFJ-DocsPublic/
  3. Re-copy to frontend/public/docs/enhanced-kiro/ when ready to republish
  4. Deploy

A sync script could automate steps 2–3 later if the docs change frequently.
